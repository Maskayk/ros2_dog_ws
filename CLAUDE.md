# CLAUDE.md

This file provides guidance to Claude Code (claude.ai/code) when working with code in this repository.

## Project Overview

ROS 2 Humble / Gazebo Classic 11 simulation of a quadruped robot ("robot dog"). 12-DOF (4 legs × 3 joints: hip_roll, thigh_pitch, shin_pitch) with modular trot gait controller and ros2_control integration.

## Build & Run Commands

```bash
# Build entire workspace
cd /root/dog_ws && colcon build --symlink-install

# Build single package
colcon build --symlink-install --packages-select dog_brain

# Source workspace (required after build)
source /root/dog_ws/install/setup.bash

# Launch full simulation (Gazebo + controllers + trot_node)
ros2 launch dog_bringup gazebo.launch.py

# Launch URDF viewer (RViz)
ros2 launch dog_description view_dog.launch.py

# Send velocity commands
ros2 topic pub /cmd_vel geometry_msgs/msg/Twist "{linear: {x: 0.3}}"

# Tune gait parameters at runtime
ros2 param set /trot_node trajectory.step_height 0.05
ros2 param set /trot_node gait.period 0.6

# Enable IMU stabilization
ros2 param set /trot_node stabilization.enabled true
```

## Architecture

### Packages

- **dog_description** — URDF/Xacro robot model (`dog_leg` macro, IMU plugin, ros2_control interfaces).
- **dog_bringup** — Gazebo launch, controller config (`controllers.yaml`), world file.
- **dog_brain** — Modular gait controller: pure C++ library (`dog_brain_lib`) + ROS node (`trot_node`).

### dog_brain Modules

```
include/dog_brain/
    types.hpp           # RobotGeometry, LegJoints, FootPosition, VelocityCommand, LEG_SIGN_X/Y
    leg_kinematics.hpp  # solveIK(), solveFK()
    gait_generator.hpp  # phase offsets per leg; trot = {0, 0.5, 0.5, 0}
    foot_trajectory.hpp # swing: smoothstep-X + polynomial-Z; stance: linear push-back
    body_controller.hpp # IMU roll/pitch → per-leg Z correction
src/
    trot_node.cpp       # thin ROS node: parameter loading, timer callback, publish
```

### Data Flow

```
/cmd_vel → [trot_node @ 50Hz] → /joint_group_position_controller/commands
                ↑                          ↓
           /imu/data        [gazebo_ros2_control PID p=80 d=2 @ 100Hz]
                                           ↓
                              [Gazebo ODE @ 1ms] → /joint_states
```

**trot_node startup sequence** (elapsed time from node start):
- `0 → ramp_duration` (2 s): smoothstep ramp of joint angles from SPAWN pose (thigh=0.5, knee=-1.1) to standing pose
- `ramp_duration → ramp_duration + settle_time` (0.5 s): hold standing
- after: normal gait loop

### Joint Ordering

All 12-element arrays (controllers.yaml, types.hpp):
`FL_hip, FL_thigh, FL_shin, FR_hip, FR_thigh, FR_shin, RL_hip, RL_thigh, RL_shin, RR_hip, RR_thigh, RR_shin`

## Critical Implementation Details

### Spawn & PID Setup
- **Spawn height**: `z=0.42`. Physical joints land at 0/-0.1 (shin clamped to upper limit=-0.1).
- **initial_value in URDF**: `thigh=0.0, shin=-0.1` — must match physical spawn position. Mismatch → large PID error → robot flips.
- **trot_node SPAWN_THIGH/SPAWN_KNEE must match URDF initial_value** (both = 0.0/-0.1).
- **PID p=40, d=2** on all joints (controllers.yaml). Without PID, Gazebo uses SetPosition (instant teleport) → robot flies.
- **`<dynamics damping="0.5"/>` on every joint** — REQUIRED for `implicitSpringDamper` to work. Without it, implicitSpringDamper is a no-op (Gazebo checks damping==0 → skips). Provides continuous viscous damping at every ODE substep (1ms), preventing micro-oscillation between PID updates (10ms).
- **implicitSpringDamper=true** on every joint via `<gazebo reference="...">` — essential for ODE stability.

### IK Sign Convention
- Thigh axis `xyz="0 1 0"`. Positive angle → foot tip moves in **-X** (backward in world frame).
- `solveIK`: `thigh = atan2(foot.x, -foot.z) + acos(cos_beta)` — matches FK.
- `foot.x` in FootTrajectory is in the FK coordinate system (positive = physically backward).

### FK/Trajectory Sign Convention
- Forward motion (`vx > 0`): `total_x` must be **negative** in foot_trajectory.cpp.
- Stance: foot.x goes −total_x → +total_x (body moves forward).
- Swing: foot.x goes +total_x → −total_x (foot swings forward).

### Inertia
- Leg links: fixed `ixx=iyy=izz=0.005` for all (hip, thigh, shin). Do NOT compute cylinder izz — thin shin gives ≈0.00002 → ODE explosion at contact.

### Foot Contact
- Shin: **sphere-only** collision at tip (radius=0.03). No cylinder collision (creates spurious contacts).
- Contact params inline in `<collision>`: `kp=500000, kd=100, minDepth=0.003, maxVel=0.0, mu=1.0`.

### xacro Header & gazebo_ros2_control
- xacro (CLI and Python API) adds `<!-- | This document was autogenerated... | -->`.
- The `|` char breaks rcl argument parser when gazebo_ros2_control spawns ControllerManager in-process.
- **Fix in gazebo.launch.py**: `xacro.process_file(urdf_file).toxml().replace('|', '')`.

### Launch Sequence
```
RSP (with clean URDF) → Gazebo → spawn_entity → JSB → controller_spawner → [4s delay] → trot_node
```
The 4s delay lets robot fall and settle before trot_node starts sending commands.

## SolidWorks Mesh Integration

1. Export each part as STL, place in `src/dog_description/meshes/`.
2. Replace primitive geometry with `<mesh filename="package://dog_description/meshes/part.stl" scale="0.001 0.001 0.001"/>`.
3. Keep collision geometry as simplified primitives.
4. Recalculate inertia from SolidWorks mass properties (do NOT use computed cylinder formula).
